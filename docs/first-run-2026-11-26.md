# 首次使用检查（2026-11-26）

把 `classroom/one-backbone` 分支克隆到空目录，照 README 从上到下做一遍：建虚拟环境、装依赖、用 nbconvert 整本执行 Notebook，再用命令行把十一个方向各跑一次。为了模拟第一次来的人，pip 不使用本地缓存，torch 从 PyTorch 官方源下载。Windows 和 WSL（Ubuntu 24.04）各做一次，所有步骤退出码都是 0，执行后的 Notebook 没有报错，并生成了图。

| 步骤 | Windows | WSL Linux |
|---|---:|---:|
| 克隆 | 1 秒 | 6 秒 |
| 建虚拟环境 | 3 秒 | 3 秒 |
| 装 CPU 版 torch | 27.5 分钟 | 35.5 分钟 |
| 装项目（pip install -e .） | 15.5 分钟 | 7.9 分钟 |
| 装 Jupyter | 8.0 分钟 | 6.4 分钟 |
| 整本执行 Notebook（默认扩散场） | 1.7 分钟 | 4.0 分钟 |

环境：Windows 为 Python 3.12.10，Linux 为 Python 3.12.3；两边都装上 torch 2.15.0（CPU 版）、NumPy 2.5.5、scikit-learn 1.9.1。下载 torch 占了大部分时间，在当时的网络下要 27 到 36 分钟。

## 命令行逐方向运行

`python -m nanoscigpt.tasks.eleven --field <方向>`，种子 53，预训练 200、800、3,200 三档，每个方向用 2 个线程，依次运行。

Windows 上的 44 个数（每个方向的预训练损失和下游误差）与五种子实验中种子 53 的记录一致，只有打印时截到 5 位小数造成的差别。Linux 上的预训练损失与之相差最多 2.3%，单种子下游误差最多差 22%（DNA 的 200 档）。两边 torch 版本相同，差别来自不同平台上的浮点计算顺序；32 个标签、单个种子时，这种小差别会在下游误差上放大。五种子的结论不靠单次数字。

表中晶体一行是当天的默认任务（晶格常数）。2026-11-27 晶体的默认任务改为形成能，在这两个环境里重跑同一条命令，三档下游误差在 Windows 和 Linux 上都是 0.607 / 0.597 / 0.560，Windows 的数字与五种子实验中种子 53 的记录一致。
