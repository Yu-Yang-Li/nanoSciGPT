## 为什么测试流式

只读检查当前安装的opencodex源码：`src/server/chat-native.ts`第171行将未配置的`connectTimeoutMs`取为200000；第228—236行把它传给`fetchWithHeaderTimeout`。该函数在等待响应头时设置计时器，收到响应头或异常后清除。当前配置没有显式设置该字段。

上一轮非流式请求约204秒出现`Timeout elapsed`，与这个等待限制吻合。这是源码和时长支持的定位，不是抓包证明，也不是“上游服务宕机”的证明。此次流式响应在约7秒就开始返回，并持续超过200秒，说明在这一请求中确实避开了先前的等待失败。**传输能够持续，不等于模型能在本次额度内交付代码。**

没有增加输出额度，没有套用未经支持的关闭推理参数，没有改研究内容或替换原版执行器。无代码可审查，因此没有继续运行新实验，也没有自动重试。
