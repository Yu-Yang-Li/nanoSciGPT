好，这轮先只做方案，不动你本地的任何东西。下一轮比较我建议这么安排：先用最便宜的方式确认 0.7 这个数可不可比，再进入单变量改动。

**第 0 步：先测噪声，不改任何东西。** 分两小步，开销最小：

- 同一个 checkpoint 用 evaluate.py 对那组固定样本再算一遍 MAE。两次结果应当完全一致；如果不一致（比如推理时 dropout 没关、batch 顺序有影响），要先修评价，否则后面所有比较都不可信。
- 然后用原样不改的 train.py 命令再训练一次，evaluate 后得到第二个 MAE。两次训练的差值就是这套流程的噪声水平，之后任何改动带来的变化要明显大于它才算真改进。

**第 1 轮：一个改动，二选一。** 你的评价指标是 MAE，但多数回归模板默认用 MSE 训练——MSE 学的是条件均值，MAE 奖励的是中位数，而酶活性分布常有偏态和离群值，这两者经常打架。所以第一轮值得测的是“训练目标和评价指标是否匹配”，两个候选只挑一个，不要同时改：

- 把 train.py 的损失从 MSE 换成 L1 或 Huber；
- 或者保留 MSE，但先把目标值做 z-score 标准化，评价时反变换回原始尺度再算 MAE。

开销都是一次训练，其余全部不动。

**第 2 轮看第 1 轮结果再定。** 比如第 1 轮有效，下一轮可以试学习率调度或按验证 MAE 早停；无效的话先回头查数据划分，而不是继续堆改动。

每轮遵守同一条纪律：数据准备、evaluate.py、固定样本组完全不动，每次只改一个变量，训练时长保持相同额度，每轮记一行结果（改了什么、命令、MAE、日志在哪），类似 autoresearch 的 results.tsv。你只把数字告诉我就可以，不需要数据和代码——分工是你本地跑、报结果，我负责提改动、判断保留还是撤回。AI Scientist 的 Agent 流程这轮先不启动，等真要接的时候再确认哪些内容会随 API 请求发出去。
