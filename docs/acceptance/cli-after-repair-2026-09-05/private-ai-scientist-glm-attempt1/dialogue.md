# 连续CLI教学实测

模型：scnet/GLM-5.3

## 第1轮

学生原文：

请按当前仓库 skills/ai-scientist-research-loop/SKILL.md 带我做研究。我想用 AI Scientist 改进蛋白质性质回归模型，但数据和代码都不能上传，现在只方便告诉你上一次的 MAE 是 0.7。你觉得先怎么办？

CLI实际回复：

我先读了仓库里的 [SKILL.md](skills/ai-scientist-research-loop/SKILL.md)，里面正好写了这种情况的处理方式：学生只给一个分数时，先接住问题、弄清这个分数是怎么来的，再决定下一步，不要求上传数据或代码，也不一次性把模型结构、数据规模、评价方法全问完。所以现在不需要你上传任何东西，我们先把 MAE 0.7 这个数字本身弄清楚。

我的建议是：先讨论，不上传。这个 MAE 平时是用什么命令或步骤算出来的？比如是哪个脚本、在哪个数据划分（训练集/验证集/测试集）上算的、每次跑是否用同一套命令。你回答这个之后，我们再决定值得先了解什么、以及“0.7”有没有可比的基线。

另外提前说一句：AI Scientist 实际运行时会把代码和日志发给模型 API，“数据和代码不上传”这条约束到接入前要专门确认发送范围。如果确实不能发送、也没有合适的本地模型，就由你在本机跑实验、在允许范围内把结果反馈给我，我来帮你分析和提改动方案——这条路同样能推进研究。

先等你说说这个 0.7 是怎么得到的。

## 第2轮

学生原文：

我在本地用 train.py 训练，用 evaluate.py 对固定的一组样本算 MAE，目标是酶活性。暂时不运行，先帮我安排下一轮比较。

CLI实际回复：

好，这轮先只做方案，不动你本地的任何东西。下一轮比较我建议这么安排：先用最便宜的方式确认 0.7 这个数可不可比，再进入单变量改动。

**第 0 步：先测噪声，不改任何东西。** 分两小步，开销最小：

- 同一个 checkpoint 用 evaluate.py 对那组固定样本再算一遍 MAE。两次结果应当完全一致；如果不一致（比如推理时 dropout 没关、batch 顺序有影响），要先修评价，否则后面所有比较都不可信。
- 然后用原样不改的 train.py 命令再训练一次，evaluate 后得到第二个 MAE。两次训练的差值就是这套流程的噪声水平，之后任何改动带来的变化要明显大于它才算真改进。

**第 1 轮：一个改动，二选一。** 你的评价指标是 MAE，但多数回归模板默认用 MSE 训练——MSE 学的是条件均值，MAE 奖励的是中位数，而酶活性分布常有偏态和离群值，这两者经常打架。所以第一轮值得测的是“训练目标和评价指标是否匹配”，两个候选只挑一个，不要同时改：

- 把 train.py 的损失从 MSE 换成 L1 或 Huber；
- 或者保留 MSE，但先把目标值做 z-score 标准化，评价时反变换回原始尺度再算 MAE。

开销都是一次训练，其余全部不动。

**第 2 轮看第 1 轮结果再定。** 比如第 1 轮有效，下一轮可以试学习率调度或按验证 MAE 早停；无效的话先回头查数据划分，而不是继续堆改动。

每轮遵守同一条纪律：数据准备、evaluate.py、固定样本组完全不动，每次只改一个变量，训练时长保持相同额度，每轮记一行结果（改了什么、命令、MAE、日志在哪），类似 autoresearch 的 results.tsv。你只把数字告诉我就可以，不需要数据和代码——分工是你本地跑、报结果，我负责提改动、判断保留还是撤回。AI Scientist 的 Agent 流程这轮先不启动，等真要接的时候再确认哪些内容会随 API 请求发出去。

定第 1 轮的具体改动前，需要你确认两件事：train.py 现在用的损失是什么（MSE 还是别的）、目标值有没有做过标准化；另外那组固定评估样本和训练数据是完全不相交的吧？
