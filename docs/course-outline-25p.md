## 全局设计合同

- **案例与实践分离**：案例只讲（公认代表作、有独立评测、说明阶段跃迁），实践当场做（普通笔记本10分钟出结果、每步一个新概念、失败也有教学价值）。
- **实操成线**：A线实操围绕 nanoSciGPT 从 V0 一路升级到路线决策；B线实操围绕 autoresearch 从假设到论文闭环。两线实操各自独立，通过"模型成为工具"汇流。
- **时间线即课程结构**：每页对应发展史一个节点，讲"相比上一代解决了什么痛点、怎么解决的"，不是教科书式原理复述。
- **证据分层**：所有输出标注"设计 / 已运行 / 已评测 / 已外部验证"，不混层。
- **诚实边界**：不承诺90分钟训练真实科学基座。"继续用专用模型"和"暂不构成闭环"都是合格结论。
- **模拟与真实分离**：PPT/HTML中的示意动画标"SIMULATION"；仓库命令现场跑的输出标"REAL RUN"；预录备用结果标"REPLAY"。三者永不混用。
- **证据阶梯**：模型输出 → 已运行 → 已评测 → 已外部验证 → 科学结论。每一级升级都需要独立证据，同源评价触发自我确认警告。

## 第一部分：开场（P1–P4，0–10分钟）

### P1｜Agent能搭模型，但不能替你定义什么算对

**时间：0–2分钟**

**旧瓶颈**：研究生会用Agent写代码、跑模型、出分数，但科研任务依然不成立——因为问题没定义、评价器缺失。

**技术跃迁**：本课的两条时间线——A线（能力复用半径）解决"建什么模型"，B线（科研过程长度）解决"怎么闭环"。

**论文锚点**：两条线的终点锚点——A线 Evo2 (Nature 2026)，B线 Robin (Nature 2026)。

**本页主张**：工程流程完成 ≠ 科学任务成立。今天的课教你怎么判断"该建什么、什么时候信它、什么时候停"。

**讲解要点**：
- 开场演示：给Agent一句模糊指令"帮我拟合@data/下的分子数据"，它顺利返回模型+分数+报告。
- 追问：数据身份是什么？评价器谁定的？没有改变下一步的反馈，这算科研吗？
- 壌出课程主线句：**A线回答"科学数据怎么变成模型的语言、什么时候值得基座"；B线回答"工具和评价器怎么串成会自我修正的闭环"。**

**学生动作**：写下自己的研究方向和一句科学问题。

**实操增量**：无命令。开场演示一句模糊指令"帮我拟合@data/下的分子数据"的Agent输出，展示"工程流程已执行/科学任务尚未定义"。

**停止边界**：Agent可以澄清问题，不能替学生虚构数据、评价器或科学结论。

### P2｜你的课题缺的是可复用能力，还是更长的科研过程？

**时间：2–4分钟**

**旧瓶颈**：学生不知道自己的课题卡在哪——是模型能力不够，还是科研流程太人工。

**技术跃迁**：双轴定位——横轴"能力复用半径"（专用→多任务→跨域→统一），纵轴"科研过程长度"（人工→可执行→工具链→反馈闭环→持续状态）。

**讲解要点**：
- A线和B线是两条独立的升级路线，不是成熟度排名。右上角不天然优于左下角。
- 位置只描述当前瓶颈，不描述优劣。
- 今天两线分开讲、最后汇流：模型成为工具，评价器成为否决门。

**学生动作**：在双轴图标出自己课题当前的位置。

**停止边界**：不做基座排名，不把多Agent当独立发展阶段。

### P3｜先定义什么算对，再让Agent去做

**时间：4–7分钟**

**旧瓶颈**：模型输出0.92置信度——但"对"的标准是谁定的？

**技术跃迁**：评价器先行原则。评价器决定是否继续、停止、最大可声称结论。

**讲解要点**：
- 证据阶梯：模型输出 → 已运行 → 已评测 → 已外部验证 → 科学结论。
- 同一模型自评 = 自我确认风险（SELF-CONFIRMATION）。
- 只填benchmark时最多到"已评测"，不能到"已外部验证"。

**学生动作**：填最低可接受评价器和不可越过的结论边界。

**停止边界**：通过一个评价器只证明通过该评价器；同源评价可能只是自我确认。

### P4｜把课题压成一张可执行入口卡

**时间：7–10分钟**

**旧瓶颈**：研究设想太模糊，Agent没法接手。

**技术跃迁**：九字段入口卡把研究翻译为Agent可读合同。

**讲解要点**：九字段——科学问题、科学对象、数据单位、现有数据、目标输出、当前瓶颈、最低评价器、真实反馈、结论边界。"暂无反馈"和"数据不可共享"都是合法约束，不报错。

**学生动作**：完成入口卡九字段。

**停止边界**：入口卡完整只表示问题可继续设计，不表示模型可行或闭环成立。

## 第二部分：A线——领域基座模型（P5–P12，10–38分钟）

### P5｜A前史：专用模型证明任务可学习（约2016–2021）

**时间：10–14分钟**

**旧瓶颈**（当时）：深度学习在CV/NLP大获成功，科学领域"任务可学习吗"都还是问题。

**技术跃迁**：AlphaFold2（蛋白质结构预测，CASP14 达到接近实验精度）、Pangu-Weather / GraphCast（中期天气预报超越数值预报）证明：给足够的领域数据和任务定义，端到端深度模型可以解决以前认为不可解的科学问题。

**论文锚点**：AlphaFold2 (Nature 2021)、Pangu-Weather (Nature 2023)、GraphCast (Science 2023)

**讲解要点**：
- 这一代的共同点：单一任务、端到端监督训练、专用架构。AF2不做生成，Pangu只做预报。
- 这一代的价值：证明"科学任务可学习"，为"可复用基座"创造了需求。为什么要复用？因为每个任务都从零训练太贵。
- **衔接下一页**：但如果每个新任务都要重新收集数据+重新训练，成本不可持续——这就是基座模型的前史性动机。

**实操增量**：无现场实操。可展示 CGCNN 6秒训练结果（晶体→图→形成能，测试MAE 1.798）作为"专用模型"的实物演示，不展开。

**停止边界**：专用模型的成功不证明基座必要性；AF2接近实验精度不等于功能理解。

### P6｜A1a：文本预训练——nanoGPT 跑通"下一个字符预测"

**时间：14–18分钟**

**旧瓶颈**（上一页留下）：每个任务从零训练太贵。

**技术跃迁**（约2018–2020）：自监督预训练——不需要标签，从数据本身构造学习信号（预测下一个token）。

**论文锚点**：GPT (2018)、BERT (2019)、nanoGPT（karpathy 教学实现）

**讲解要点**：
- 预训练到底在做什么：从1MB莎士比亚学"统计结构"。loss下降、生成伪莎士比亚——模型学到的是语言的规律，不是语义。
- 关键观察：预训练损失下降 ≠ 学到有用表征。有没有用要靠下游探针检验（P9伏笔）。

**实操增量**：

```bash
python -m nanoscigpt.domains.text.prepare
python -m nanoscigpt.core.trainer --domain text --max_iters 100
python -m nanoscigpt.core.sampler --domain text
```

学生亲眼看到 loss 4.20→2.66、采样出伪莎士比亚。

**停止边界**：伪莎士比亚"像但没意义"正是预训练学到的统计结构；这一级只证明机制，不证明能力。

### P7｜A1b：科学对象语言化——换 tokenizer 就换领域

**时间：18–22分钟**

**旧瓶颈**（上一页留下）：预训练很好，但我的对象不是文本——是蛋白、DNA、分子。

**技术跃迁**（约2019–2022）：科学对象被序列化/标记化——氨基酸字母表、DNA碱基、SMILES化学式都是离散符号序列，同一套方法可处理。

**论文锚点**：UniRep (Nat Methods 2019)、TAPE (NeurIPS 2019)、ProtTrans (TPAMI 2021)、ESM-1b (PNAS 2021)

**讲解要点**：
- 核心洞察：**架构不变，只换 tokenizer 和数据，就从文本模型变成了蛋白模型**。
- 现场指着代码问学生："trainer.py 改过一行吗？没有。变了的只有 domains/protein/prepare.py——这60行就是'领域插件'的全部。"
- 流式（text/DNA）与独立序列（protein/SMILES）的数据处理差异——prot-gpt 的核心魔改。

**实操增量**：

```bash
python -m nanoscigpt.domains.protein.prepare --size 500
python -m nanoscigpt.core.trainer --domain protein --max_iters 100
python -m nanoscigpt.core.sampler --domain protein
# DNA、SMILES 同理
```

四域实测：text 2.66 / protein 2.84 / dna 1.32 / smiles 1.68。同一核心，四个领域。

**停止边界**：500条UniProt不会学到蛋白质生物学。这一级证明"机制可迁移"，不证明"能力可迁移"。

### P8｜A2a：换预训练目标——CLM vs MLM

**时间：22–25分钟**

**旧瓶颈**（上一页留下）：语言模型从左到右预测，但科学对象未必有因果方向——蛋白序列的上下文是双向的。

**技术跃迁**：预训练目标可插拔。CLM（GPT家族，单向因果）vs MLM（BERT/ESM家族，双向掩码恢复）。架构完全相同，差异只有attention mask和loss位置。

**论文锚点**：ESM (PNAS 2019/2021) 用MLM、GPT家族用CLM

**讲解要点**：
- 不是谁更好，而是下游用法不同：要生成就选CLM，要表征就选MLM。ESM选MLM所以能做结构预测；GPT选CLM所以能写文章。
- objectives/ 目录就是这个思想的代码化：causal_prediction 和 masked_prediction 是可切换的插件。

**实操增量**：

```bash
python -m nanoscigpt.tasks.objective_contrast
```

输出：CLM 2.97→2.76；MLM 3.01→2.81（同一蛋白数据）。

**停止边界**：300 iter 的小模型不会显出两者真实差距；这一级展示"目标可以切换"，不是"哪个目标更优"。

### P9｜A2b：表征迁移——预训练到底带来了什么

**时间：25–29分钟**

**旧瓶颈**（上一页留下）：预训练损失下降，但下游能用吗？

**技术跃迁**（约2022–2024）：表征可迁移——冻结预训练模型，取中间层embedding训简单分类器，比one-hot更好，才证明"预训练有迁移价值"。基座性由迁移合同证明，不由参数量证明。

**论文锚点**：ESM-2 (Science 2023)、ClimaX (ICLR 2023)、scGPT (Nat Methods 2024)

**讲解要点**：
- 基座证据 = 迁移合同：至少两个共享结构的下游任务 + 冻结探针 + 从头训练对照 + OOD检验。
- ESM-2 用2.5亿序列证明了这个合同成立。我们的450条序列呢？
- **迁移合同的完整字段**：①两个共享结构的下游任务；②适配方式三选一（冻结探针 / 完整微调 / 参数高效适配PEFT）；③标签预算阶梯（100% / 10% / 1%）；④逐任务报告，禁止平均掩盖负迁移；⑤OOD检验（新对象/时间/区域/仪器留出）。
- **划分即评价的一部分**：随机划分 vs 对象/同源簇/时间/区域留出，同一模型换划分可能从"好"变"泄漏"。评价器不只看分数，还看划分。

**实操增量**：

```bash
python -m nanoscigpt.tasks.transfer_probe
```

**输出（本机实测）**：one-hot 100% / 随机编码器 98.3% / 预训练编码器 95%——**迁移增益为负**。

**这是全课程最重要的一页**：450条序列的"预训练"不如one-hot。这不是失败，这正是课程要证明的事——数据规模不够时，"预训练"只是自我安慰，正确路线是回到专用模型。ESM的2.5亿条与我们相差六个数量级。**机制相同、规模决定成败**。

**停止边界**：负迁移结果直接衔接P11路线决策——五问中"迁移证据"一栏，学生应诚实回答"否"。

**诚实的对照**：ESM-2 8M（4,170星/MIT）真实权重一行加载即可提取残基级表征，作为"足够数据下迁移合同成立"的对照演示。

**Agent提示词模板**（学生课后用）：

```text
基于课题入口卡和预训练设计，为候选任务1、任务2设计领域基座迁移合同。
检查任务是否共享结构；设计从头训练、冻结探针、完整微调、参数高效适配三种对照；
比较100%/10%/1%标签预算；报告时间/算力/显存/新增参数；
设计对象/时间/区域OOD留出；逐任务报告，禁止平均掩盖负迁移；
给出最低基座证据和退回专用模型条件。
没有真实结果时只输出实验设计，不得生成分数。
```

### P10｜A3a：多任务统一——基座的最小结构隐喻

**时间：29–32分钟**

**旧瓶颈**（上一页留下）：每来一个新任务就训一个新模型，表征不能复用。

**技术跃迁**（约2023–2026）：基座能力统一——共享编码器 + N个轻量任务头。任务行为差异来自头部，表征复用来自编码器。

**论文锚点**：ESM3 (Science 2025)、Aurora (Nature 2025)、Evo2 (Nature 2026)

**讲解要点**：
- 共享编码器能不能服务多任务？multihead 实验给出答案。
- **有价值的失败案例**：parity任务（顺序敏感）在均值池化下只有45%——均值池化丢失顺序信息。这不是bug，是"表示瓶颈"的活教材：多任务学不动时，先问池化是否丢了任务需要的信息，再问模型够不够大。

**实操增量**：

```bash
python -m nanoscigpt.tasks.multihead
```

输出：共享编码器 cls_acc=1.000 + reg_mae=0.2714（合成双任务）。

**停止边界**：合成双任务验证结构可行性，不是真实科学任务的增益。

### P11｜A3b：路线决策——五问决定要不要基座

**时间：32–35分钟**

**旧瓶颈**（整条A线的终极问题）：到底什么时候值得做基座？

**技术跃迁**：证据驱动的路线决策。四条路线是平行选择：继续专用 / 调用现成 / 适配基座 / 训练新基座。新训练是最后选项，不是默认目标。

**讲解要点**：
- 五问决策链：无标签数据是否万级以上？是否有两个共享任务？迁移是否优于从头？是否有算力和维护责任？OOD下是否稳定？
- 任何一问失败都有降级路径。你的课题大概率停在专用模型——这是合格结论，不是失败。

**实操增量**：

```bash
python -m nanoscigpt.tasks.route_decision
```

输出：数据不足→正确降级为专用模型。

**停止边界**：模型更大、数据很多或能够微调，都不能直接支持训练新基座。

### P12｜A线收束 + 过渡：你的V0→T4就是科学模型史的缩影

**时间：35–38分钟**

**旧瓶颈**（整条A线留下）：学生走完了六级实操，但不知道自己走的路和真实历史是什么关系。

**技术跃迁**：历史对照——学生刚走的路径就是真实科学模型史的缩影，区别只在规模。

**论文锚点**（对照表）：

| 你的实操 | 历史对应 | 规模差距 |
|---|---|---|
| nanoGPT文本版 | GPT家族 | 数万亿token vs 1MB |
| 蛋白版（换tokenizer） | ESM/ProtTrans | 2.5亿序列 vs 450条 |
| transfer_probe | ClimaX/scGPT的迁移合同 | 同一方法，差六个数量级 |
| multihead | ESM3/Aurora统一基座 | 结构同构，能力天差 |
| route_decision | 你自己的课题 | —— |

**讲解要点**：
- 对照表：nanoGPT文本版↔GPT、蛋白版↔ESM、迁移实验↔ClimaX/scGPT、多任务↔ESM3/Aurora、路线决策↔你自己的课题。
- **学生刚走的路径就是真实历史**：专用模型→语言化→换目标→迁移→统一→决策。区别只在规模。
- **过渡**：A线产出的模型只是工具，科研是循环。下一半课讲怎么把工具串成闭环。

**实操增量**：无新增命令。回看P6–P11的六条命令输出，串成一条证据链。

**停止边界**：对照表证明的是结构同构，不是能力对等。"你走的路和ESM一样"不等于"你的模型和ESM一样"——规模差距就是停止边界。

**学生动作**：完成A线模型设计卡（问题、I/O、基线、表示、迁移证据、路线、停止条件、下一行动）。

**A线一句话**：**科学对象可预训练化 → 表征可迁移化 → 基座能力按真实需求统一化。**

## 第三部分：B线——AI Scientist（P13–P19，38–70分钟）

### P13｜B前史 → S1：从窄目标自动化到假设生成

**时间：38–42分钟**

**旧瓶颈**（历史）：科研入口靠人读文献——读不过来、有盲区、想法质量靠运气。

**技术跃迁**：
- **前史**（约2015–2020）：Adam/Eve（ yeast 杂交优化）、mobile robot chemist（Nature 2020）证明窄目标自动化可行，但目标预设、无开放假设。
- **S1 假设生成**（约2023–2026）：从数据统计生成想法 → 结构化评分 → 专家验证 → 假设库。LLM生成的想法不是假设，经过评分、重写、专家验证的才算。

**论文锚点**：AstroInsight (EPJ Data Science 2026)、Adam (PNAS 2024)、mobile robot chemist (Nature 2020)

**讲解要点**：
- AstroInsight 四阶段：conception（数据统计生成想法）→ refinement（novelty+feasibility-vagueness评分）→ expert validation（人类专家1–6分）→ knowledge integration（进入idea bank）。
- 核心教学点：**conception的输入是数据统计，不是空想**。每个想法带grounding。
- 前史与S1的分界：前史是"人设目标、机器执行"；S1是"系统参与生成目标本身"。

**实操增量**：

```bash
python -m autoresearch.hypothesis --domain protein --auto_approve
```

输出三个假设，其中 IDEA-C 预测"这个规模做不出基座模型"——负向假设比正向假设更接近真实科研。

**停止边界**：S1产物是"经过验证的假设"，不是"科学发现"。想法被接受≠被支持；支持要靠S2实验证据。

### P14｜S2：实验闭环——反馈改变下一步

**时间：42–47分钟**

**旧瓶颈**（上一页留下）：假设生成了，但实验还是人工一步步做。

**技术跃迁**（约2023–2025）：反馈进入下一步——分析结果改变下一轮动作。

**论文锚点**：StarWhisper Telescope (Comms Eng 2025)、SAMPLE (Nature 2025)、小来 (Nature Synth 2025)、Coscientist (Nature 2023)、ChemCrow (NMI 2024)

**讲解要点**：
- StarWhisper 闭环：观测计划→function call执行→实时分析→动态follow-up。闭环判定标准不是"跑了多少步"，而是"反馈是否改变了下一步"。
- 反馈身份四级分类：真实实验/观测（物理）、模拟/形式化（计算）、历史回放（REPLAY）、模型自评（自我确认风险）。只有前两类有资格支撑"闭环"主张。
- 固定自动化 vs 反馈驱动对照：固定模式连续三轮仍用参数A；反馈模式按结果从A改B、触发安全边界回滚、增益停滞停止。
- 工具合同（tools.py CONTRACTS）：不在合同里的操作被拒绝——AI Scientist安全边界第一层。
- **SILENT ERROR 演示**：300K 直连摄氏输入——工具全部"调用成功"，但单位没有转换，数值悄悄错五个数量级。工具成功≠数据正确；每个合同必须写I/O、字段、单位、版本。
- **权限四级**：自动 / 只读 / 执行前批准 / 禁止。按可逆性和失败成本分配，不是所有节点都人工批准。
- 形式化评价器（evaluator.py）：design/ran/evaluated三级，绝不混层。
- 失败被保留：gain +0.0000（fail）——200 iter不比100 iter好，这本身就是发现。

**实操增量**：

```bash
python -m autoresearch.experiment --domain protein --auto_approve
```

观察三个点：计划是数据结构（每个步骤有reason）；人工门真实存在（train_extended需批准）；失败被保留。

**停止边界**：S2证明"循环可执行且反馈改变行动"，但不能证明"科学增量"——教学fixture永远到不了外部验证层。

### P15｜人的责任移动到关键决策

**时间：47–51分钟**

**旧瓶颈**：自动化程度越高，"人到底管什么"越模糊。

**技术跃迁**：scientist-in-the-loop——责任不是处处点确认，而是具体到权限和签署。

**论文锚点**：自驱实验室安全综述 (Nat Rev Chem 2025)、AI Scientist verification gap (ScienceAgentBench/DiscoveryBench/PaperBench)

**讲解要点**：
- 权限矩阵：自动 / 自动并通知 / 执行前批准 / 仅人工。按可逆性、失败成本、安全伦理、结论影响分配。
- 高风险操作（预算增加、设备控制、发布）必须过人工门。
- 课堂演示：去掉 --auto_approve，人工门真实等待学生输入。

**实操增量**：

```bash
python -m autoresearch.run --domain text --fresh
# 不带 --auto_approve：人工门真实等待输入
```

**停止边界**：有人参与不自动证明可信；人工确认不替代评价器和原始证据。

### P16｜B线交付：闭环设计卡

**时间：51–55分钟**

**旧瓶颈**：系统做完说不清"到底到了哪一层"。

**技术跃迁**：四级层级自动降级判定——可执行步骤 / 可追溯工具工作流 / 目标明确反馈闭环 / 跨轮研究状态。

**论文锚点**：对应四级的真实系统——L1 RoboRXN等实验自动化、L2 Coscientist/ChemCrow工具编排、L3 SAMPLE/小来/StarWhisper反馈闭环、L4 The AI Scientist/Robin持续状态。

**讲解要点**：
- 无评价器不到L1；工具不可追溯不到L2；反馈不改下一步不到L3；假设/反证/失败不跨轮不到L4。
- "暂不构成闭环"是合格结果，停在工具工作流不丢人。
- 跨轮研究状态（state.py + research_state_<domain>.json）：重跑不--fresh直接恢复终态。

**学生动作**：完成B线闭环设计卡（目标、动作/评价器、工具合同/权限、反馈/更新规则、研究状态、人工责任、最高层级、不能声称什么）。

**停止边界**：设计原型不等于自主科学发现。

### P17｜两轨汇流：模型成为工具

**时间：55–58分钟**

**旧瓶颈**：A线和B线各讲各的，学生不知道两者怎么接。

**技术跃迁**：基座模型是Agent可调用的能力，不是独立的科学发现系统；Agent调用模型不等于模型输出已验证。

**论文锚点**：汇流形态的案例——GNoME（基座模型+筛选闭环）、MatterGen（生成+评测闭环）、StarWhisper（模型工具+观测闭环）。

**讲解要点**：
- 正确链：问题 → 数据对象 → 模型工具 → Agent行动 → 独立评价器 → 反馈 → 状态更新 → 人工关口 → 下一行动。
- 两种典型断链：模型输出直连结论；同模型生成+自评。
- **汇流固定句**：基座模型提供可复用能力，Agent组织工具和行动，evaluator与真实反馈决定证据升级，研究者承担设题、授权、复核和签署责任。

**学生动作**：把A线模型卡和B线闭环卡映射到同一蓝图。

**停止边界**：两轨汇流不构成新的模型代际，也不自动产生科学证据。

### P18｜教师实演：autoresearch 完整 pipeline

**时间：58–62分钟**

**旧瓶颈**：学生看了分模块演示，还没见过完整闭环。

**技术跃迁**：三段式pipeline——S1想→S2做→S3说，共用同一个ResearchState。

**本页主张**：一次演示串起三段——S1想→S2做→S3说。

**讲解要点**：
- 讲师现场跑 protein 域全流程，指着输出串："S1想出三个假设并让专家评分（IDEA-C说做不出基座）→ S2执行了四个合同工具、经历一次人工门、保留一次失败 → S3把这些证据组装成稿、发现三处overstate、逐条返修、事实审计通过、写下能声称什么/不能声称什么。"
- **这就是一个完整的、每一层都可追溯的AI Scientist最小闭环。**

**实操增量**：

```bash
python -m autoresearch.pipeline --domain protein --fresh --auto_approve
```

四域实测结果：protein 的 H2（预算加倍）和 H3（迁移）被标记为 **refuted**——450条序列撑不起基座主张。系统用证据说"不"。

**停止边界**：教学数据是fixture；本仓库刻意不用LLM（规则驱动让每步可读可追溯）；S3审稿是结构化审稿不是同行评审。

### P19｜学生实操：自己跑通 autoresearch 全流程

**时间：62–66分钟**

**旧瓶颈**：看老师跑和自己跑是两种理解。

**技术跃迁**：亲手跑通后，三道门的判定逻辑从概念变成身体感。

**论文锚点**：对应三段——S1 AstroInsight、S2 StarWhisper、S3 The AI Scientist/Robin。

**学生动作**：

## 第四部分：压力测试与收束（P20–P25，70–90分钟）

### P20｜蓝图与四道人工审计

**时间：66–70分钟**

**旧瓶颈**：Agent能生成漂亮蓝图，但没人审计过。

**技术跃迁**：红队审计——向蓝图注入已知问题，学生定位并处置。

**论文锚点**：verification gap 的评测底座——ScienceAgentBench (ICLR 2025)、DiscoveryBench、PaperBench。

**讲解要点**：
- 向蓝图注入一个典型问题：单任务新基座、随机划分冒充OOD、REPLAY冒充在线、模型自评、候选冒充发现、失败删除、高风险无授权。
- 学生定位问题节点并选择保留/降级/删除/补证据。
- 四道门：模型路线门、反馈真实性门、评价器独立性门、结论与责任门。

**八类注入题库**（红队审计标准题，学生用这套题检查自己的蓝图）：

| # | 注入问题 | 检查点 | 正确处置 |
|---|---|---|---|
| 1 | 单任务课题声称要训练新基座 | 任务数量与共享结构证据 | 降级为专用模型 |
| 2 | 随机划分冒充OOD检验 | 划分方式与对象/时间/区域留出 | 重设计划分 |
| 3 | REPLAY历史数据冒充在线反馈 | 反馈身份标注 | 降级为计算闭环 |
| 4 | 同一模型生成+自评 | 评价器独立性 | 引入独立评价器或降级声称 |
| 5 | 候选列表冒充科学发现 | 证据阶梯层级 | 停在"已生成候选" |
| 6 | 模拟结果冒充实验验证 | SIMULATION/REAL RUN标签 | 标注为计算证据 |
| 7 | 失败记录被删除 | 研究状态完整性 | 恢复失败记录+选择偏差警告 |
| 8 | 高风险操作无人工授权 | 权限矩阵 | 标DESIGN_BLOCKED |

**审计规则**：状态只能标注为 BLUEPRINT_REVIEWED，不是 SYSTEM_VALIDATED。审查通过≠系统已验证。

**学生动作**：审计自己的蓝图，标出至少一个停止点和一个签署点。

**停止边界**：状态为 BLUEPRINT_REVIEWED，不是 SYSTEM_VALIDATED。

### P21｜蛋白压力测试：四种模型角色

**时间：70–74分钟**

**旧瓶颈**：学生做完自己的设计后，需要用公认案例检验设计的每个环节是否混层。

**技术跃迁**：蛋白线四代角色递进——每一代解决上一代的瓶颈，也暴露新瓶颈。

**压力测试链**：AlphaFold2（专用结构预测）→ UniRep/TAPE/ESM（预训练迁移）→ ESM3（多模态条件生成）→ RFdiffusion（约束候选生成+后验评价）

**必须区分**：专用结构预测、无标签预训练、迁移评测、多模态/生成统一、应用汇流。

**学生修改任务**：检查自己的对象表示、迁移任务和生成后评价器是否混层。

**实践锚点**：回看P7——我们刚在450条UniProt上做过"蛋白语言化"；P9的负迁移结果说明这个规模做不出基座。你刚跑的不是AlphaFold，但走的路是同一条。

**停止边界**：结构≠功能；表征≠机制；生成≠实验；候选数量≠发现。

### P22｜天气压力测试：预报、基座与混合模拟

**时间：74–78分钟**

**旧瓶颈**：蛋白线是序列对象，天气是时空场——表征方式完全不同，迁移思想是否通用？

**技术跃迁**：天气线证明同一套"专用→基座→统一→混合"逻辑跨表征方式成立。

**压力测试链**：Pangu/GraphCast（专用全球预报）→ ClimaX（预训练适配）→ Aurora（Earth-system多任务基座）→ NeuralGCM（物理混合模拟）

**必须区分**：专用预报、跨任务领域基座、多任务Earth-system能力、物理-ML混合模拟。

**学生修改任务**：检查时间/区域OOD、初始条件依赖、资料同化依赖、长期稳定性。

**实践锚点**：我们没跑天气模型，但P9的迁移合同思想完全适用——ClimaX证明的就是"冻结+适配优于从头"的天气版。

**停止边界**：专用预报≠基座；平均优势≠局部可靠；分析初值依赖≠完整自主系统；天气表现≠未来气候外推。

### P23｜AI Scientist压力测试：工具、反馈和状态

**时间：78–82分钟**

**旧瓶颈**：AI Scientist系统报道多、层级乱，学生分不清工具编排、反馈闭环、持续研究三个概念。

**技术跃迁**：三层能力链——工具编排→反馈改下一步→跨轮研究状态。多Agent只是实现方式，不构成独立层级。

**压力测试链**：Coscientist/ChemCrow（工具编排）→ SAMPLE/小来/StarWhisper（真实反馈改变下一步）→ The AI Scientist/Robin（持续研究过程）

**必须区分**：工具执行、目标明确闭环、持续研究状态。

**学生修改任务**：检查工具合同、反馈是否改变下一步、失败是否跨轮保留、人的责任位置。

**实践锚点**：回看P14/P19——autoresearch 的三段就是这三层的教学版：tools.py是工具编排、experiment.py的decide()是反馈闭环、state.py是跨轮状态。你刚跑的每一步都在对应真实系统的一个能力层。

**停止边界**：工具≠闭环；窄目标物理闭环≠开放科学家；长流程/多Agent≠可信；候选/体外≠临床或理论结论。

### P24｜作业：最小闭环证据包

**时间：82–86分钟**

**旧瓶颈**：课程作业容易变成"交一份漂亮方案"，奖励复杂性而惩罚诚实。

**技术跃迁**：证据包评价——七项提交物把"能复核"变成评分主体，失败和反证是必交项而非扣分项。

**本页主张**：作业评价证据可复核性，不奖励结果漂亮或系统复杂。失败和反证是必交项。

**七项提交物**：双轨蓝图；真实/脱敏输入样例；Agent Prompt与完整轨迹；可执行评价器与结果；失败/反证；反馈后的下一步；能/不能声称什么。

**评分**（100分）：问题与数据边界15；基座模型与迁移设计20；工具、反馈与状态闭环20；评价器、运行证据和可复核性25；停止条件、责任与结论边界20。

**实践锚点**：作业可直接基于 nanoSciGPT 仓库——用自己的域跑通pipeline、改一个参数生成对照、把research_state和训练日志作为证据包核心素材。

**停止边界**：截图、自动报告、无输入身份分数、全成功记录或无评价器系统图不能单独构成证据包。

### P25｜结语：离开教室前，只确定下一项最小行动

**时间：86–90分钟**

**旧瓶颈**：课程结束时学生只记得"学了很多模型名"，不知道周一回到实验室该做什么。

**技术跃迁**：最小行动原则——下一项行动必须可执行、可检查、一个下午能完成。

**本页主张**：只确定下一项最小行动。停止升级也是行动。

**讲解要点**：
- 回到P2双轴坐标：灰点起点、蓝点当前设计。
- 三种合格终态：专用+工具工作流；适配基座+计算闭环；可复用能力+真实反馈闭环。
- 学生写下：模型路线一句话、系统层级一句话、能声称什么、不能声称什么、下一项可执行最小行动。

**最终句**：

> 先找科研瓶颈，再选择模型路线；再设计评价器、反馈和停止条件。只有外部证据越过验证门槛，结果才会从模型输出升级为科学增量。

**停止边界**：完成课程意味着拥有可执行、可否决、可继续迭代的科研系统设计；不意味着已训练基座、实现自主科学家或获得新科学结论。
