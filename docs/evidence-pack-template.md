## 从实际文件生成运行记录索引

在仓库根目录可以用下面的命令汇总运行记录。它只生成证据包中的运行部分，不会替你补写研究想法、完整对话、人工决定或下一步。还没有这些材料时，保留为空或写明未完成。

```powershell
python -m nanoscigpt.evidence_pack --run-report <课程运行报告> --downstream-result <最新微调的downstream_result.json> --attachment <原项目的一份日志或结果文件> --output <新的Markdown路径>
```

- 没有继续微调时可省略`--downstream-result`，沿用运行报告指向的结果；有最新结果时明确传入，避免只展示最初任务头的分数。
- `--attachment`可重复提供，也可省略。autoresearch的`results.tsv`、v1实验日志、v2搜索记录、代码差异、图表和稿件都保留原格式。脚本只记录附件路径、大小和SHA256，不把附件数量当作研究已完成的证据。
- 无标签任务被跳过时，不生成监督分数，也不标为已评测。运行未完成、结果缺少有效数值时，按实际情况记录；再次微调变差时同样保留。
- 没有下一步决定记录时显示“未记录”，由学生根据结果补充，不自动编造已作出的决定。
- 输出必须使用新路径，不覆盖旧作业；原附件不修改、不自动复制或上传。提交作业时，按允许共享的范围另附日志和脱敏样例；只交包含本机路径的索引不能让别人复现。

原版Agent是否真的提出了想法、执行了实验、根据结果继续研究，需要查完整原始轨迹。只运行实验模板时，就写“实验模板已运行”，不要写成“AI Scientist已完成研究”。
