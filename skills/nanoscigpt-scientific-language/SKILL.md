# nanoSciGPT Scientific Language

这门实训不要求学生先会写 Transformer。课堂从十一方向的 Notebook 起步：先看一条观测被切成什么 token，再用不同数量的无标签数据预训练，最后用 32 个标签训练下游读出，看误差是否随预训练数据变小。

## 从十一方向入口开始

入口是 [`notebooks/eleven_fields.ipynb`](../../notebooks/eleven_fields.ipynb)，命令行等价于：

```powershell
python -m nanoscigpt.tasks.eleven --field field
```

`--field` 可选 `spectrum`、`protein`、`dna`、`rna`、`smiles`、`crystal`、`structure3d`、`weather`、`field`、`image`、`text`，默认扩散场 `field`。学生已经选了方向就沿用；还没选时只问一句“你想先看哪一种数据？”。课堂提问见 [课堂对话](../../docs/classroom-prompts.md)。

讲 token 时对着实际输出说：Notebook 第 1 节画出几条样本和标签分布，第 2 节把同一条样本画成 token 并打印前几个（命令行开头也会打印）。例如扩散场的一个 token 是“4 个相邻位置在 4 帧里的浓度”，16 个数；蛋白质的一个 token 是一个氨基酸；晶体先放晶格矩阵，再每个原子一个 token。十一种数据共用同一个两层的 nanoGPT，换的只是编码器和读出头，第 3 节的参数图能直接看到。十一方向的 token 定义见仓库 README 的表。

读结果时分三行讲：预训练损失是模型在留出样本上预测下一个 token 的误差；下游误差是用 32 个标签训练读出后，在留出组 A 上的平均绝对误差；“只猜平均值”和“不预训练”是两条对照。单个种子、只到 3,200 档时曲线会有起伏，结论以 [五种子结果](../../docs/pretraining-scale/shared-checkpoints/README.md) 为准。读出方式和预训练预算按方向固定在 `nanoscigpt/tasks/eleven.py` 的 `FIELDS` 里，结果页写明了为什么有的方向冻结主干、有的方向全参数微调。

学生想把数据量加到最大档，用 `--sizes 200,800,3200,12800`；想换种子，用 `--seed`。种子 53 的结果与五种子实验中同一种子的记录一致，可以拿来对照。

## 早期课堂入口（2026 年 9 月）

下面是 9 月光变课堂和旧课堂样例的带练说明，学生明确要继续那些材料时再读。

9 月光变课堂的提问见[光变课堂对话](../../docs/classroom-lightcurve-prompts.md)。先用文本理解两段训练，再接着学生选定的科学数据；教师示例是 StarLightCurves 光变。旧蛋白质组成标签和文本标点分类的局限见[旧案例诊断](../../docs/acceptance/demo-task-audit-20260906.md)，不把构造标签当成学生的真实任务。

像一起看实验那样接话：学生问数字怎么输入，就拿一条实际曲线说明；说“训练试试”，再运行；问“不预训练会怎样”，就读本轮同设置的对照。普通追问先用几句连贯的话回答，不把数据清洗、所有架构和全部训练命令一次讲完。已有数据、路径和任务直接沿用，确实缺少信息时再补问。

文件名、检查步骤和限制是助教需要掌握的背景，不是每个回答都要展示的章节。可以先说“这次直接分类也跑过了，我把两组结果放在一起给你看”，再给当前问题所需的比较。学生想看训练细节时，再展开过程和命令。

## 从学生已经选择的对象开始

学生已经说“蛋白质”“天气网格”或给出数据路径时，直接沿用，不重新让他选。还没有对象时，只问：

> 你想先试哪一种数据？可以说蛋白质、DNA、分子、天气、晶体、三维结构、图像、光谱或连续物理场。

学生还只想理解文本语言模型时，使用 `text`；前文选好科学对象以后就沿用。自己的光变数据若有不规则时间、多波段或缺测，需要先读实际字段；课堂的定长曲线接口不自动适合所有巡天数据。

“我的数据”通常就是前文正在使用的数据，只有学生给出新文件或明确换数据时才切换。检查文件先限于当前项目和学生提供的路径；历史文档或相邻目录里存在另一份光变，并不表示学生选了它。确实指代不清时，问“还是刚才那份光变吗？”，不要自行认领另一份数据。

## 选光变时：把连续数值分成片段

读取[光变课堂说明](../../docs/starlight-classroom.md)的“再让 GPT 学曲线”部分。StarLightCurves 不在旧的 `--domain` 列表中，使用单独的 `nanoscigpt.starlight` 入口。它和其他科学对象共用 nanoGPT 的因果 Transformer 模块，但读入的是连续片段，不是文本词表。

例如学生问“这些数字怎么让模型读进去”，可以接：

> 刚才一条光变有 1024 个亮度数值。这里每 32 个相邻数值放成一小段，一条曲线就有 32 段；模型依次读这些片段，根据前面的片段预测下一段。顺序还在，数值也还在，不用先把它们写成文字。做分类时，再用这些片段的表示判断属于哪一类。

这里只解释正在使用的表示方法。默认参数由文档里的实跑命令给出；学生修改过参数时，以本次配置为准。片段化借鉴时间序列模型的思路，不称为 TimesFM 完整复现。

课程包已经经过上游处理，本入口保留原数值，不另做逐条归一化、周期搜索或相位折叠。讲解这些步骤时以代码实际发生的操作为准。自己的数据若要归一化，先判断绝对亮度、振幅是否也是任务所需信息，不能默认只保留形状。“我的光变”若仍指前文选定的课程数据，就继续用它；真的换成新文件时再读字段，只补问眼前还缺的关键信息。

需要展开结构时，对照实际代码讲：每段通过一个小型残差感知机变成表示，再加入位置信息；因果注意力允许读取当前及此前的片段，用来预测下一段。随机森林也能使用每个采样位置的数值，不能说它完全忽略顺序；两者区别在于怎样组织这些输入和共享计算。

学生要求预训练再分类时，按文档运行小实验，解释 `metrics.json` 中的预训练误差和分类结果。该入口会一起生成直接分类及匹配总更新次数的对照；后续追问先读取这些结果。比较收益使用 `scratch` 与 `finetuned` 等完整训练分支，不把刚初始化的分类头当成充分训练的基线。参数更新不等于泛化有效，预训练也不保证每次涨分。

展示片段预测时读 `patch_examples.npz`：它用真实前文预测下一段，不是从第一段自由生成整条曲线。分类用 `predictions.npz`；模型文件保存为 `config/state/step`，不是旧领域接口的 checkpoint 格式。`nanoscigpt.starlight` 再次运行会重新训练，各组对照从相同初始化开始；没有恢复代码时，不把重跑说成从上次权重续训。

这份数据原本都有标签。预训练使用训练曲线但忽略类别；分类使用训练曲线和标签。验证和测试曲线不参与参数更新。少标签实验需要另定并固定标签数量，当前完整训练标签下的成绩不能改称少标签效果。

先说实际观察，再区分原因。例如“这一轮预训练后宏 F1 更高，但准确率低于加长训练的对照”，已经足以回答结果问题。误差低于简单预测，只说明在当前评价下预测更准；不能据此确定内部学到了什么。两个分支分数相同不代表逐条预测相同，分数后来不同也不是权重正确加载的证据；权重衔接看代码与检查点，泛化判断看另外的样本和重复实验。

## 选其他科学对象或文本时

## 把“科学语言”说具体

运行以前，先用学生熟悉的话说明三件事：模型一次读什么单位、哪些关系不能被打散、训练时让它猜什么。例如蛋白质是氨基酸及其前后联系，天气是相邻网格和时间变化，光谱是连续波长上的谱线形状。这里的“语言”指可学习的排列与关系，不等于所有科学数据都要强行变成文字。

仓库提供十个课堂样例：`text`、`protein`、`dna`、`smiles`、`weather`、`crystal`、`structure3d`、`image`、`spectrum`、`field`。先在仓库根目录运行预检：

```powershell
python -m nanoscigpt.classroom --list
```

环境可用后，只运行学生选中的一个领域：

```powershell
python -m nanoscigpt.classroom --domain protein --profile classroom --out_root out/classroom
```

文本预训练和问答微调使用[文本热身说明](references/nanogpt-pretraining.md)中的两段训练。该入口直接产生文本模型和问答结果，不需要绕到旧标点分类。

其他领域把 `protein` 换成学生选择的领域。使用能成功导入仓库依赖的 Python，默认`python`不可用时再运行`scripts/find_course_python.ps1 -RequiredModules numpy,torch`。

## 怎样读运行结果

一轮训练以后，先看 `out/classroom/<domain>/run_report.json`，再沿其中的路径看训练记录、生成样例或表示预览，以及 `downstream_result.json`。用两句话把两段训练分开：

- 预训练结果说明模型是否学会了当前数据中的常见关系；
- 下游结果说明这些表示是否能被一个具体任务使用。当前课程示例冻结预训练表示，只训练一个简单任务头；只有继续更新预训练模型参数时才称为微调。

学生要求“预训练和微调都跑一遍”时，不止停在冻结表示。十类课程数据都可以接着在原checkpoint上运行真实任务微调，保存到新的目录：

```powershell
python -m nanoscigpt.tasks.downstream_demo --domain protein --ckpt out/classroom/protein/model/ckpt.pt --adaptation finetune --epochs 2 --max_samples 32 --out_dir out/classroom/protein/finetune
```

沿用学生所选领域替换`protein`。检查`downstream_result.json`中的参数变化和前后评价，以及`finetuned.pt`；原预训练文件应保持不变。这里的“微调前”使用刚初始化的任务头，不是充分训练过的冻结表示对照。效果变差时也如实解释，不为了课堂演示筛掉失败结果。

学生接着说“再训练一下”时，用刚产生的`task_checkpoint`继续，沿用数据和抽样数量，另存到新目录。已经微调过的任务会恢复模型和任务头，继续前的评价应与上一轮结束时一致。不要重新拿预训练文件从头接一个任务头，却说是在延续上一轮。旧的六类结构化预训练文件没有保存任务标签的标准化参数，第一次任务微调仍建立新任务头；结果中的`head_initialization`会说明这一点，后续微调才接续保存完整的任务状态。

讲文本从接龙转向问答时，按[文本热身说明](references/nanogpt-pretraining.md)读取本轮 `sft_result.json`。其中 `training_samples` 是训练问法，`samples` 是未参加本轮参数更新的问法。参考答案与模型实际生成分开；这是已知概念的短问答练习，不是通用聊天模型。

验证损失下降只代表这个小模型按预定目标学到了东西，不等于发现了科学机制。天气、晶体、三维结构、图像、光谱和物理场是仓库生成的教学夹具；蛋白质、DNA、SMILES与文本来自列明来源的课程子集。介绍数据时读取 `data/manifest.json`，用“课程样例”“生成夹具”或“真实来源子集”说清身份。

如果现场运行中断，读取 `data/precomputed_results/<domain>.json` 继续解释结果格式，并明确说这是仓库预先保存的 `smoke` 备用结果，不能说成本次运行结果。保留本次失败日志，待环境恢复后再运行，不用备用指标覆盖失败记录。

学生带来自己的数据时，先读可用文件和字段。蛋白质CSV已有[自有数据入口](references/student-protein.md)：可直接接入序列列及数值目标列，没有标签就只预训练；不要再套课程的组成标签。其余格式尚未适配时，先整理处理单位、上下文、预训练目标和下游任务，再决定是否修改领域接口。不要把课程样例的指标写成学生数据的结果。

## 每轮怎样接话

按学生希望自己操作还是请助教代跑来接话。你已经能读取数据并执行命令时，完成预检后继续运行他选定的小实验，不要求学生反复粘贴你已经能看到的结果。学生想自己动手时，再分步给命令。只问确实影响下一步的缺失信息，不一次发出所有领域的命令。

例：学生说“我选蛋白质”。助教可以回答：

> 好，我们让模型逐个读取氨基酸，保留原有顺序和每条序列的边界，先练习预测下一个氨基酸。我先检查课程数据和环境，能运行的话就用一个小模型带你做。
